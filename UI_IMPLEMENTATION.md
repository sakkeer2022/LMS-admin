# Dashboard UI and development contract

The existing authenticated admin home renders the dashboard. The admin layout checks the signed-in user and role with the backend (`GET /auth/me`) and permissions come from that user. There is no demo authentication bypass.

The dashboard uses the explicit development adapter in `src/features/dashboard/adapter.ts`, not invented backend endpoints. Each panel has its own tenant-scoped TanStack Query key and abort signal. Summary values and recent activity are deterministic September 2026 fixtures; session responses return `{ rows, total }` after filtering and slicing with a six-row page size. Money is integer paise. Replace the adapter with authenticated, tenant-scoped backend contracts before production. Repeated session names represent synthetic data.

URL state: `page` and `status` control session requests. `demoState=loading|empty|error` exercises panel geometry and failure states; `failPanel=summary|alerts|activity|sessions` exercises partial failures. Retry reissues the same request; remove the failure parameter to restore responses. Summary CSV contains exactly the four displayed demo metrics and their details, not a financial ledger. Export is disabled when summary data is unavailable.

Header search searches configured navigation only. Notifications show an empty state until a feed exists. `/admin/settings` is the Figma Settings screen (node 1211:34102): its values are design defaults, there is no settings endpoint yet, so Save stays disabled and the page says so. "My profile" (`/admin/profile`, built from the Figma Settings content, node 207:6913) holds personal details, role and permissions, sign-in security, signed-in devices and recent activity; logout uses the CSRF-protected logout API. Additional navigation destinations render explicit integration extension screens under the original protected admin layout. Alert links require matching read permissions and carry their queue in `filter`; no moderation capability is implied.

Brand and grouped admin navigation live in `lib/auth/portal-config.ts`. Figma tokens live in `app/globals.css` (Tailwind v4 `@theme`); there is no dark theme because the design has none. The sidebar collapses to an icon rail on desktop (tooltips name each item) and opens as a `Sheet` drawer below `lg`; Radix provides Escape dismissal, focus containment and focus restoration. The Faculty and Reviews counts beside navigation items come from the dashboard alerts adapter.

Visual differences: the sidebar toggle button is absent from the reference, and the Figma notification unread dot, the Settings "Change history" action and its "last edited by" line are not built (no data behind them). The header avatar shows the signed-in person's initials. Pending domain workflows remain explicitly unavailable. Visual browser verification requires a running backend and an admin account.

Validation: `npm run typecheck`, `npm test` and `npm run build` pass. Pages were compared against the Figma frames in headless Chrome at 1440 px (login, dashboard, settings) and checked at 390 px (dashboard, mobile drawer) and in the collapsed icon rail, using a throwaway mock API. Faculty is a deterministic query-backed directory with URL status/category filters. Only seven fixture profiles are supplied; counts describe those fixtures rather than claiming 118 real records. Invitation and verification mutations are unavailable. The Playwright browser scripts and the AST lint (`scripts/check-ui.cjs`) were retired with the old components.
